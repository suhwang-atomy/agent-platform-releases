1. 시작하고 비서와 일하기 / 01

AOA로 어떤 일을 할 수 있나요

AOA는 내 컴퓨터 안에 AI 직원과 일할 사무실을 만드는 도구입니다. AOA는 Atomy Office Agent의 줄임말입니다.

  1. 내가 목표 정하기
  2. 직원에게 맡기기
  3. 기록과 결과 확인
  4. 다음 업무에 활용

내 역할은 대표입니다

내가 원하는 결과와 기준을 정하고 직원에게 업무를 맡깁니다. 직원은 연결된 AI를 이용해 조사·정리·문서 작성 등을 수행합니다. 부서나 직원을 많이 만들어야 시작할 수 있는 것은 아닙니다.

직원은 역할이 있는 AI입니다

자료를 정리하는 직원, 보고서를 쓰는 직원처럼 맡을 일을 설명해 구성합니다. 인사카드에는 역할과 일하는 방식이 담깁니다. 기본 비서는 필요한 일을 정리하고 직원 구성과 보고를 돕습니다.

대화가 업무와 문서로 이어집니다

대화에서 업무를 지시하고, 업무기록에서 진행과 결과를 확인합니다. 저장한 지식과 산출물은 문서함에서 다시 찾을 수 있습니다. 중요한 결과는 근거를 확인한 뒤 사용하세요.

로컬 저장과 AI 연결

사무실 자료와 설정은 이 기기에 저장됩니다. 연결한 AI와 외부 서비스에는 요청을 처리하는 데 필요한 입력이 전달될 수 있습니다. 로컬 앱이라는 말이 모든 AI가 인터넷 없이 동작한다는 뜻은 아닙니다.

처음 목표는 작게 잡으세요. ‘직원 한 명에게 자료 세 줄을 정리하게 하고 결과를 확인하기’면 충분합니다.

1. 앱과 사무실 준비

공식 배포판을 설치하고 사무실을 만듭니다. 처음에는 기본 비서로 시작해도 됩니다. 설정 화면에서 언어와 사용할 AI 연결을 확인합니다.

2. 비서에게 짧은 업무 한 건

비서에게 “다음 메모를 핵심 세 줄로 정리해 줘”라고 요청하고 짧은 예시 메모를 붙입니다. 응답이 나오고 업무기록에서 해당 실행을 찾을 수 있는지 확인합니다. 연결 오류가 있으면 먼저 AI 연결을 해결합니다.

3. 조직 자료가 필요한 경우에 연결

조직 지식을 쓸 때는 Google 업무 계정의 사무실 사용 승인과 조직지식 다운로드 연결을 순서대로 진행합니다. Google 로그인만으로 AI 실행 연결이 대신되지는 않습니다.

4. 반복 실행은 시험 뒤에

자동회의에 참여할 직원은 필요한 자료를 읽을 수 있는지 먼저 시험합니다. 루틴은 같은 업무를 한 번 직접 실행한 뒤 일정·시간대를 정합니다. 실행 시간에는 컴퓨터와 앱을 켜 둡니다.

준비 확인: 비서의 답변 → 실행 기록 → 필요한 자료의 원문 → 작은 시험 업무의 결과. 막힌 단계부터 해결하면 됩니다.

앱을 설치하고 준비하기

컴퓨터에 맞는 설치 파일과 사용할 AI 계정을 준비합니다. 처음부터 모든 외부 서비스를 연결할 필요는 없습니다.

1 설치 파일 받기

공식 다운로드 페이지에서 Apple Silicon Mac용 DMG 또는 Windows용 설치 파일을 받습니다. Mac은 DMG를 열어 AOA를 응용 프로그램으로 옮기고, Windows는 설치 파일의 안내를 따릅니다. Intel Mac과 Linux용 공개 설치 파일은 이 안내의 대상이 아닙니다.

2 첫 실행 안내 따라가기

처음 여는 사무실이 없다면 업무 계정 연결 → 개발 환경 → 러너 연결 → 사무실 개설 순서의 안내를 봅니다. 개발 환경은 일부 AI 연결이 실행될 수 있도록 준비하는 단계입니다. 설치 중에는 끝날 때까지 기다리세요.

3 연결할 계정 정하기

업무 계정은 Google·Slack 자료를 사용할 때, AI 연결은 직원이 생각하고 일을 수행할 때 필요합니다. 둘은 서로 다른 연결입니다. 계정·러너 연결을 나중으로 넘길 수 있지만 실제 AI 업무에는 사용 가능한 러너가 필요합니다.

4 작은 연습 사무실로 시작하기

처음에는 ‘업무 연습실’처럼 구분하기 쉬운 이름을 사용하세요. 실제 고객 자료 대신 직접 쓴 짧은 예문으로 연결과 응답부터 확인하면 사용 흐름을 익히기 쉽습니다.

직원이 사용할 AI 연결하기

러너는 AOA가 AI를 실행하는 연결 방식입니다. 처음에는 사용할 서비스 하나만 연결하세요.

1 연결 화면 열기

첫 실행의 러너 연결 단계 또는 설정 → AI 연결로 이동합니다. 사용할 서비스의 카드를 펼쳐 설치·로그인 상태를 확인합니다.

2 화면이 안내하는 방법 선택

브라우저 로그인은 해당 서비스의 로그인 화면에서 동의하는 방식입니다. API 방식은 발급받은 키를 연결 설정에 입력하는 방식입니다. 서비스마다 지원 방식이 다르며, Gemini는 API 방식으로 안내됩니다.

3 설치가 필요하면 안내대로 준비

설치 안내가 나오면 현재 운영체제를 선택해 명령과 공식 안내를 확인합니다. 명령 복사는 설치 완료가 아닙니다. 안내된 설치를 마친 뒤 다시 확인하고 연결 상태가 바뀌었는지 보세요.

4 연결 후 첫 응답 확인

직원에게 짧은 정리 작업을 지시합니다. 연결 오류가 나면 같은 요청을 반복 전송하기보다 설정에서 인증 상태와 이용 한도를 확인하세요.

로그인 방식과 API 방식의 과금은 다를 수 있습니다. 한도가 소진됐다고 API 방식으로 자동 전환되는 것으로 생각하지 마세요.

새 사무실과 직원 구성하기

사무실 하나에 함께 일할 직원과 문서를 모읍니다. 회사 법인이나 조직도를 준비해야 하는 것은 아닙니다.

1 사무실 이름 입력

오피스 선택 화면에서 새 사무실 이름을 입력해 개설합니다. 일반 생성 경로에서는 처음 직원 구성을 돕는 대화가 이어집니다. 미리 준비된 구성을 선택한 경우에는 직원 대화로 바로 이동할 수 있습니다.

2 업무와 목표 설명

예를 들어 ‘매주 여러 자료를 모아 팀 공유용 보고서를 쓰고 싶어요’라고 적습니다. 필요한 역할과 업무 범위를 제안받으면 빠진 일이나 과한 역할을 답변으로 조정하세요. 직원 구성 제안받기를 누른 뒤, 수정할 내용은 답변 반영해 제안 수정으로 반영합니다.

3 제안 확인 후 확정

제안된 직원의 이름과 맡을 일을 확인합니다. 수정 입력을 먼저 반영한 뒤 이 구성으로 직원 만들기를 누릅니다. 처음부터 직원 수를 늘리기보다 필요한 역할만 남기는 것이 좋습니다.

나중에 직원을 추가하려면

대시보드의 ‘어떤 전문가가 필요하세요?’ 입력란에 맡길 일을 적고 직원 추가를 누릅니다. 사무실 생성 때의 구성 대화를 매번 다시 진행하지는 않습니다.

무엇을 만들지 막막하면 기본 비서에게 ‘내 반복 업무를 설명할 테니 필요한 직원을 제안해 줘’라고 이야기하세요.

무엇부터 할지 비서와 정하기

기본 비서는 사무실에 공통으로 있는 업무 상담·채용 지원·보고 담당입니다. 표시 이름이 달라도 역할은 같습니다.

언제 비서에게 말하나요

해야 할 일이 막연하거나 누가 맡으면 좋을지 모를 때 비서 대화를 엽니다. “매주 자료를 모아 보고하는 일이 오래 걸려. 도와줄 방법부터 정리해 줘”처럼 현재 상황을 말해 보세요.

어떻게 직원 구성으로 이어지나요

비서는 누구의 어떤 반복 업무가 어려운지, 원하는 결과물이 무엇인지 짧게 확인하고 역할과 예시 업무를 제안합니다. 제안을 확인한 뒤 채용을 요청합니다. 부서나 모델 이름부터 정할 필요는 없습니다.

어떤 보고를 부탁하나요

“이번 주 직원별 결과와 근거, 아직 내가 결정할 일, 다음 행동 세 가지를 정리해 줘.” 비서는 직원들의 기록과 산출물을 취합해 보고하는 역할입니다. 보고의 출처와 실제 결과 파일도 함께 확인합니다.

비서는 사무실에 유지되는 기본 직원입니다. 모든 일을 비서에게만 시킬 필요는 없습니다. 담당자가 정해진 업무는 그 직원에게 직접 맡겨도 됩니다.

짧은 답이면 충분합니다

비서가 요즘 하는 일이나 반복되는 불편을 물으면 “월요일마다 숫자를 모으는 데 시간이 걸려요”, “보고는 결론부터 세 줄이면 좋아요”처럼 답합니다. 실제로 공유한 업무 맥락을 바탕으로 대화가 이어집니다.

답하지 않거나 잠시 멈추기

질문 하나씩 답을 기다리는 방식입니다. 바쁘면 “이 질문은 건너뛰어 줘”라고 말하세요. “잡담 그만”, “잡담 다시 시작”으로 자동 질문을 중단하거나 재개할 수 있습니다.

언제 먼저 말을 거나요
